## 1. ЕДИНАЯ СИСТЕМА

### 1.1 Иерархия поверхностей (surface ladder)

Глубина строится **ступенями фона + волосяной линией**, а не тенями и не блюром. Тени остаются только у того, что реально висит над чужим контентом (HUD, карточки диктовки). Внутри окон теней нет вообще.

| Слой | Где | Чем реализуется |
|---|---|---|
| L0 «холст» | фон окна | ничего не рисуем — системный `windowBackgroundColor` |
| L1 «навигация» | сайдбар Настроек | системный материал `NSSplitViewItem(sidebarWithViewController:)` / `.listStyle(.sidebar)`, **свой фон не ставим** |
| L2 «контент» | панель деталей, тело Онбординга и Словаря | `.background` (ShapeStyle), непрозрачно |
| L3 «группа/карточка» | секции настроек, карточки словаря | `.background.secondary` + hairline `Color(nsColor: .separatorColor)`, `lineWidth: 1` |
| L4 «плавающее над рабочим столом» | HUD-пилюля, карточки диктовки | `NSVisualEffectView` (см. §2.1) + двойная тень |

Правило: **разница между L2 и L3 — это шаг светлоты примерно +3…+6 %, а не тень.** Никакого `shadow(radius:)` внутри окон.

### 1.2 Шкала отступов (база 4 pt)

`2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32`

Закреплённые значения:
- Внешний padding контентной панели: **20**
- Между секциями (группами) настроек: **24**
- Внутренний padding карточки: **16**
- Между карточками: **12**
- Между строками внутри карточки: **8**
- Иконка → лейбл: **8**
- Заголовок секции → первая строка: **6**
- HUD-пилюля: горизонтально **14**, вертикально **8**

Читаемая мера текста: `.frame(maxWidth: 640, alignment: .leading)` внутри `.frame(maxWidth: .infinity, alignment: .leading)` — иначе на 900 pt ширины строки становятся нечитаемо длинными.

### 1.3 Радиусы + правило концентричности

Базовые (macOS-нативные, не веб- и не iOS-шкала — Golden Gate двигал систему именно вниз по радиусам):

| Элемент | Радиус |
|---|---|
| чип / бейдж | **6** |
| кнопка, поле ввода (small/medium) | **6** |
| кнопка Large / XL | капсула |
| карточка (внутри окна) | **10** |
| секция/группа (`Form.grouped`) | системный, не задаём |
| карточка диктовки (над рабочим столом) | **14** |
| HUD-пилюля | капсула (`height / 2`) |
| окно | **системный, никогда не хардкодим** |

**Правило концентричности:** вложенный радиус = радиус контейнера − отступ от его края. Если результат ≤ 0 — угол прямой, а не «маленький скруглённый».

Важный нюанс, который часто применяют неверно: **концентричность касается только элементов, которые физически прижаты к углам контейнера.** Чипы, плавающие в середине карточки, берут фиксированный радиус 6 — вычислять для них «10 − 16 = 0» бессмысленно.

API (macOS 26+, гейтить):

```swift
let cardShape = ConcentricRectangle(corners: .concentric(minimum: .fixed(10)),
                                    isUniform: true)
content
    .padding(16)
    .background(.background.secondary, in: cardShape)
    .overlay { cardShape.stroke(.separator, lineWidth: 1) }   // ← .stroke, НЕ .strokeBorder
    .containerShape(.rect(cornerRadius: 10))                  // ← НЕ cardShape
```

Две ловушки, подтверждённые компилятором на SDK 26.5:
1. `ConcentricRectangle` **не** conform к `RoundedRectangularShape` → его нельзя передать в `containerShape(_:)`. Контейнер объявляем через `.rect(cornerRadius:)`.
2. `ConcentricRectangle` **не** `InsettableShape` → `.strokeBorder` не существует, только `.stroke`.
3. Всегда указывать `minimum:` — иначе на прямоугольных дисплеях и вдали от углов радиус схлопывается в 0.

Fallback для macOS 14–25: обычный `RoundedRectangle(cornerRadius:)` с вычисленным вручную `outer − inset`.

### 1.4 Типографика

macOS не поддерживает Dynamic Type; база — 13 pt. Точные системные метрики (вес / размер / интерлиньяж):

| Стиль | Значения | Где применяем |
|---|---|---|
| Large Title | Regular 26/32 | заголовок первого экрана Онбординга |
| Title 2 | Regular 17/22 | заголовок панели Настроек внутри контента |
| Title 3 | Regular 15/20 | заголовок шага Онбординга |
| Headline | **Bold 13/16** | заголовок карточки, principal-item тулбара, лейбл HUD |
| Body | Regular 13/16 | основной текст |
| Callout | Regular 12/15 | пояснения под заголовком карточки, `.secondary` |
| Subheadline | Regular 11/14 | заголовки секций, статус-пилюли |

Правила:
- **Никаких `.system(size:weight:)` с ручными числами.** Только семантические стили + `.weight()`/`.bold()`.
- Иерархия строится **цветом** (`.foregroundStyle(.secondary/.tertiary)`), а не наращиванием весов.
- Запрещены Ultralight/Thin/Light.
- **Заголовки секций — Title Case, не КАПС.** Система перестала апперкейсить их сама; если в коде лежит `"ДИКТОВКА"`, теперь это буквально отрендерится капсом и будет выглядеть архаично. Нужно `"Диктовка"`.
- Онбординг — **текст по левому краю**, не по центру (WWDC25 356: type «left-aligned to improve readability in alerts, onboarding»).
- SF Rounded допустим **только** для лейбла HUD-пилюли (капсульная геометрия оправдывает), и больше нигде. Лучше вообще не смешивать.

### 1.5 Акцент

**Один акцент.** Разрешённые места:
1. Основная кнопка (ровно одна на окно/экран).
2. Фокус-ринг и выделение строки в сайдбаре/списке.
3. Индикатор активной записи в HUD.

Реализация: `Color.accentColor` — пользователь может сменить системный акцент, и иконки сайдбара обязаны за ним следовать (HIG, обновление от 8 июня 2026). Фиксированный цвет допустим точечно, если он **несёт смысл**: красный кружок записи, зелёный «Разрешение выдано» в Онбординге. Всё.

Запрещено: тонировать акцентом фон сайдбара, тулбар, шапки карточек; хардкодить системные значения цветов (они меняются от релиза к релизу — все значения, снятые со скриншотов до macOS 26, уже неверны, Apple подкрутила системную палитру под Liquid Glass); переопределять семантику (`separatorColor` как цвет текста и т. п.).

### 1.6 Словарь движения

| Событие | Анимация |
|---|---|
| hover / изменение состояния контрола | `.easeOut(duration: 0.15)` |
| раскрытие шага, переключение панели | `.smooth(duration: 0.25)` |
| появление/скрытие HUD | `.spring(response: 0.32, dampingFraction: 0.86)` |
| перестроение стопки карточек | `.snappy` |
| уровень звука в HUD | без анимации, прямое связывание (или `.linear(duration: 1/30)`) |

- Пружины по умолчанию, `.easeInOut` — только для очень коротких hover-переходов. `.bouncy` не используем нигде.
- Панель HUD: `window.animationBehavior = .utilityWindow` — даёт мягкое затухание вместо дефолтной оконной анимации.
- SF Symbols — главный носитель «свежести» без украшательства: `.symbolEffect(.drawOn)` на галочках Онбординга (macOS 26+, фолбэк `.bounce`), `.variableColor.iterative` на микрофоне во время записи (macOS 14+), `.breathe` на длительной загрузке модели (macOS 15+), Magic Replace на переходе микрофон → волна → галочка.
- Никаких конфетти и «празднований». WWDC26 250: «Delight doesn't come from confetti or flourishes at the end».

## 2. ПО ПОВЕРХНОСТЯМ

### 2.1 HUD-пилюля и карточки диктовки — **оставляем NSVisualEffectView. Не мигрируем.**

Это самый спорный пункт, и источники здесь расходятся. Разбираю явно.

**Что говорят источники:**
- HIG Windows: неактивные окна не используют vibrancy, выглядят приглушённо → «стекло тускнеет».
- Форум Apple Developer 818901 (macOS 26): в non-key `NSPanel` стекло всегда рендерится в inactive/foggy состоянии; DTS попросил репро, решения нет.
- **Эмпирическая проверка на этой машине (macOS 26.5.1, реальный бинарь, скриншоты key/non-key):** `.glassEffect()` на кастомных вьюхах **не зависит от key-состояния** — пилюля в никогда-не-key панели пиксельно идентична пилюле в key-окне. Тускнеют **стандартные стили кнопок** `.buttonStyle(.glass)` / `.glassProminent` — это обычное поведение неактивных контролов AppKit. А «плоский вид без ободка», который списывали на стекло, оказался следствием `hasShadow = false`: включение тени вернуло specular-ободок полностью.

**Разрешение конфликта.** Эмпирика точнее и форумного треда, и вывода по аналогии из HIG. Но вывод «значит, можно мигрировать на стекло» всё равно **неверен**, по четырём независимым причинам:

1. **Deployment target — macOS 14.** `glassEffect`, `NSGlassEffectView`, `ConcentricRectangle` — всё это 26.0+. Для HUD, который является главной поверхностью продукта, пришлось бы держать две полностью параллельные реализации.
2. **Golden Gate осознанно расширяет разрыв активное/неактивное** окно (через сайдбар, прозрачность и тень). Для окна, которое по определению никогда не key, это движение в неправильную сторону.
3. HIG Panels прямо предупреждает: у HUD «большинство системных контролов не соответствуют его внешнему виду» — то есть внутрь HUD системные контролы и так не положишь.
4. Текущий рецепт **уже** соответствует санкционированной Apple комбинации: `.hudWindow` material + `.behindWindow` blending — это ровно та пара, которую HIG Materials описывает как правильную для macOS.

**Что всё-таки поправить прямо сейчас:**

```swift
panel.hasShadow = true                 // ← без этого стекло читается плоским блюром
panel.backgroundColor = .clear         // иначе окно закрасит материал своим фоном
panel.animationBehavior = .utilityWindow
effectView.isEmphasized = true         // macOS 10.12+: форсирует АКТИВНЫЙ вид материала
                                       //   в non-key окне — прямой аналог отсутствующей
                                       //   «незатухающей» опции у NSGlassEffectView
```

`isEmphasized = true` — ключевая находка: это штатный, доступный с macOS 10.12 способ снять именно ту проблему, из-за которой Liquid Glass отвергли.

**Остальной рецепт HUD:**
- Форма: капсула. Вложенные элементы (чип режима, чип языка, индикатор записи) — тоже капсулы `height/2`, а не rounded rect. Геометрия должна быть согласованной.
- Скрим 0.06 — оставить, он в консервативной части рекомендованного диапазона (10–25 % «frost»; выше 30 % материал выглядит «молочным пластиком»).
- Асимметричный hairline и двойная тень — оставить: это ровно то, что HIG требует от кастомного окна («если используете кастомную реализацию, различение состояний окна — ваша работа»).
- Цвета текста — **системные vibrant**, не захардкоженный белый/серый: тогда они адаптируются к материалу автоматически.
- Контент HUD (конвенция категории — superwhisper / Wispr Flow «Flow bar»): состояние записи + уровень звука + текущий режим/язык, **ровно один контекстный контрол**, не ноль и не пять. Пайплайн Whisper → словарь → GPT показывать **именованными стадиями** («Распознаю» → «Правлю по словарю» → «Причёсываю»), а не одним спиннером — видимость работы и есть продукт в этой категории.
- HIG Panels: «Keep HUDs small», «use color sparingly» — карточки диктовки не должны разрастаться в полноценную панель.

**Если когда-нибудь поднимете floor до macOS 26** — единственный допустимый путь: `NSGlassEffectView` (`contentView` + `cornerRadius` + `style`) внутри `NSGlassEffectContainerView` со `spacing = 0` (даёт выигрыш в производительности батчингом, но без слипания карточек). И **никогда** `.buttonStyle(.glass)` внутри HUD — вот он действительно тускнеет. Правильный вариант кнопки для non-key поверхности (проверен на скриншоте при активном Finder):

```swift
Button { start() } label: {
    Label("Диктовать", systemImage: "mic.fill")
        .padding(.horizontal, 14).padding(.vertical, 8)
}
.buttonStyle(.plain)
.glassEffect(.regular.interactive(), in: .capsule)
```

### 2.2 Окно Настроек (NavigationSplitView, ~900×600)

Здесь позиция обратная HUD: **удалять кастомное, а не добавлять.** Apple явно требует: «Reduce your use of custom backgrounds in controls and navigation elements… Prefer to remove custom effects and let the system determine the background appearance», и отдельно, по AppKit: **не класть `NSVisualEffectView` внутрь сайдбара** — он блокирует системный материал.

**Сайдбар:**
```swift
NavigationSplitView {
    List(selection: $selection) {
        Section("Диктовка") { … }        // Title Case
        Section("Движок") { … }
    }
    .listStyle(.sidebar)
    .navigationSplitViewColumnWidth(min: 196, ideal: 214, max: 280)
    .toolbar(removing: .sidebarToggle)   // сайдбар настроек не должен сворачиваться
} detail: {
    DetailPane(pane: selection ?? .general)
}
.navigationTitle(selection?.title ?? "Настройки")
```
- Никакого своего фона, никакого своего радиуса у сайдбара (тот самый «двойной бортик» Tahoe — главный признак устаревшего оформления).
- Иконки строк — **цветные** SF Symbols, по умолчанию системный акцент; фиксированный цвет только там, где он уточняет смысл.
- Символы **без `.circle`-вариантов**: `mic`, а не `mic.circle` — контейнер и так виден.
- Не более двух уровней иерархии; критичных действий внизу сайдбара нет.
- Выделение — заливка rounded rect (радиус 6), не полноширинная полоса. На macOS 26+ `\.backgroundProminence` обновляется автоматически — не отслеживать вручную.

**Панель деталей:**
```swift
ScrollView {
    Form { … }.formStyle(.grouped)
        .padding(20)
        .frame(maxWidth: 640, alignment: .leading)
        .frame(maxWidth: .infinity, alignment: .leading)
}
```
- `Form` + `.formStyle(.grouped)` вместо самодельных карточек: секции сами получают правильный радиус, увеличенную высоту строк и padding macOS 26.
- Разделительную линию под шапкой панели **удалить** и заменить scroll edge effect. Иначе она удвоится с системным эффектом и даст грязь.
- Стиль: `.automatic` по умолчанию (HIG, ревизия 8 июня 2026 — «Prefer the automatic scroll edge effect style»); `.hard` — только для панелей с прикреплёнными заголовками таблиц или свободно висящим текстом над контентом. Здесь источники расходятся (WWDC25 356 продвигал `.hard` как «преимущественно macOS»), разрешаю в пользу более свежего HIG: `.automatic`, `.hard` — точечно. Один эффект на вью, не смешивать.
- Свой нижний бар (если есть) регистрировать через `safeAreaBar(edge: .bottom)`, а **не** `safeAreaInset` — только так он попадает в систему scroll edge effect.

**Тулбар:** заголовок панели в `.principal`, группы разделяются `ToolbarSpacer(.flexible/.fixed)`, единственное prominent-действие — справа. Максимум три группы. Текстовые и иконочные кнопки не смешивать в одной группе (визуально слипнутся в один контрол). Прятать **item**, а не вью внутри него, иначе останется пустой слот.

**Шрифт HIG, который мы сознательно нарушаем.** HIG Settings для macOS предписывает панельный тулбар, а не сайдбар. Мы остаёмся на сайдбаре (прецедент — сами System Settings, плюс 5 разделов в тулбарную ленту уже плохо ложатся), но обязаны выполнить остальные правила: (а) пункт «Настройки…» в меню приложения, а не кнопка в тулбаре; (б) кнопки минимизации/зума приглушены; (в) заголовок окна = текущая панель; (г) при открытии восстанавливается последняя просмотренная панель (`window.identifier` + `isRestorable` + `encodeRestorableState`); (д) фокус ставится в сайдбар при открытии окна.

Окно: `.windowStyle(.titleBar)` + `.windowToolbarStyle(.unified(showsTitle: true))`. Радиус окна — системный; нижние контролы отступать через `layoutGuide(for: .safeArea(cornerAdaptation: .horizontal))` (macOS 26+), иначе на скруглённых углах они подрезаются.

### 2.3 Окно Онбординга

Оправдание существования — прямая цитата HIG: «If your app needs access to private data or resources before it can function, consider integrating the permission request into your onboarding flow». Микрофон и Accessibility для диктовки обязательны, значит permissions-first онбординг санкционирован. Всё остальное (выбор модели, наполнение словаря, кастомизация хоткея) — **отложить и задефолтить**.

**Структура:** одна колонка, ширина 560, текст по левому краю, `.largeTitle.weight(.semibold)` + подзаголовок `.title3` в `.secondary`.

**Экран прайминга перед системным алертом микрофона** — правила Apple жёсткие и нарушаются почти всеми:
- Ровно **одна** кнопка, озаглавленная **«Продолжить»** / «Далее». Не «Разрешить» (иначе пользователь рефлекторно жмёт Allow в реальном алерте).
- **Никаких** дополнительных действий: нельзя дать «Закрыть», «Пропустить», «Отмена» на этом экране.
- Не показывать изображение системного алерта, не рисовать стрелку в его кнопку, не предлагать бонусы за согласие.
- `NSMicrophoneUsageDescription` — законченное предложение, действительный залог, точка в конце. Например: «Transcriber записывает голос, пока вы удерживаете горячую клавишу, чтобы превратить речь в текст.» Плохо: «Доступ к микрофону нужен для лучшего опыта».

**Accessibility — отдельный паттерн, системного алерта нет.** `AXIsProcessTrustedWithOptions` лишь ведёт в System Settings, выдача происходит вне приложения, а после Sequoia разрешение может само отозваться. Поэтому шаг должен быть **живым чек-листом**: строка = иконка + одна строка «зачем» + **живая статус-пилюля** (Не выдано / Выдано), которая обновляется без перезапуска (опрос/наблюдение), + кнопка «Открыть Системные настройки…» с диплинком `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`. Кнопка «Далее» неактивна, пока обязательные строки не зелёные. Все TCC-запросы собрать в **один** шаг «Разрешения», не размазывать по флоу.

**Оформление шагов:** карточка L3 (`.background.secondary` + hairline, радиус 10) — **не стекло**: это контентный слой. `.symbolEffect(.drawOn)` на галочке выполненного шага (macOS 26+) — самый дешёвый и самый убедительный признак «это приложение 2026 года»; фолбэк `.bounce`.

Окно: `.windowStyle(.hiddenTitleBar)` + `.windowResizability(.contentSize)` + `.restorationBehavior(.disabled)`. Если один раз пропустили — не показывать повторно, но оставить доступ из Настроек → «О программе».

### 2.4 Окно Словаря (карточки + чипы)

- Карточки — L3, `.background.secondary` + hairline, радиус 10, **без тени**.
- Чипы внутри карточки — фиксированный радиус 6 (см. оговорку о концентричности в §1.3), заливка `.quaternary`, текст `.subheadline`.
- Никакого стекла: карточки и чипы — контентный слой по определению.
- Список — `List`/`Table` с системной высотой строк (они укрупнились в macOS 26 — убрать любые захардкоженные высоты).
- Разделители под шапкой заменить на scroll edge effect.
- **Пустое состояние — главная недоработанная поверхность.** Рецепт: один приглушённый SF Symbol (не иллюстрация), одно предложение простым языком о том, *что словарь делает с расшифровкой*, одна основная кнопка «Добавить слово» и — самое ценное — 2–4 готовых примера-чипа, которые добавляются одним кликом. Список никогда не должен быть по-настоящему пустым.
- Поиск: системный, `.searchable`; на macOS 26+ доступен `ToolbarDefaultItemKind.search`.

## 3. ЧТО ВЗЯТЬ ИЗ ТРЕНДОВ (8 паттернов)

1. **Глубина ступенями поверхностей + 1 px hairline, ноль теней внутри окон** (Linear: «No drop shadows. Depth conveyed through surface ladder + 1px hairline borders»). *Почему:* мягкие тени 2020–2022 — самый очевидный признак датированного интерфейса, а Golden Gate удалил даже системную тень сайдбара. Заодно дешевле по GPU.

2. **Настройки — отдельное нативное окно, никогда не модалка/шит** (правило Raycast 2.0). *Почему:* settings-in-a-modal читается как веб-приложение в окне. У нас уже так — не сломать при рефакторинге.

3. **Отказ от hover-подсветки и `cursor: pointer`-логики** (Raycast убрал hover-подсветки специально, чтобы совпасть с поведением кнопок macOS). *Почему:* кнопки macOS не «загораются» при наведении так, как веб-кнопки; лишние hover-состояния мгновенно выдают неродной интерфейс.

4. **Настройка размера интерфейса** (Raycast: Default / Large / Larger, масштабирует весь UI). *Почему:* для menu-bar-утилиты, которой пользуются весь день, это лучший доступностный ход с минимальной стоимостью — плюс на macOS 26 есть `prefersCompactControlSizeMetrics` для обратной, плотной стороны шкалы.

5. **Именованные стадии пайплайна вместо спиннера** (Wispr Flow показывает «Filler identified», «Correction identified», «Repetition identified»). *Почему:* в этой категории видимая работа модели — и есть продукт; спиннер выбрасывает главный дифференциатор.

6. **HUD как узкий бар с ровно одним контекстным контролом** (Flow bar: переключатель языка в один клик прямо в баре). *Почему:* устоявшаяся конвенция категории; ноль контролов заставляет лезть в меню, пять — превращает HUD в панель, что HIG прямо запрещает.

7. **Draw On / Variable Draw у SF Symbols вместо самодельных индикаторов** («inspired by the calligraphic movement of handwriting»; Variable Draw «convey strength or progress»). *Почему:* даёт живой уровень звука и прогресс расшифровки системным API — без кастомного метра, бесплатно получая поддержку Reduce Motion.

8. **Пустое состояние как первая продуктовая поверхность, а не «нет данных»** («A well-designed empty state guides the user toward the next meaningful action»). *Почему:* у Словаря пустое состояние — это буквально первый экран каждого нового пользователя.

*Отдельно как ориентир качества:* обе награды Apple Design Awards 2026 в релевантных категориях (Moonlitt — Interaction, за онбординг и сдержанный Liquid Glass; Tide Guide — Visuals) взяты за **умеренность и осмысленность**, а не за максимум эффектов.

## 4. ЧЕГО НЕ ДЕЛАТЬ

**Прямые запреты Apple:**
1. **Liquid Glass в контентном слое.** «Don't use Liquid Glass in the content layer… Instead, use standard materials for elements in the content layer.» → карточки Словаря, панели Настроек, шаги Онбординга — никогда.
2. **Стекло на стекле.** «Always avoid glass on glass» — второй слой физически нечего сэмплить. Вложенные элементы — плоские заливки + vibrant-текст.
3. **Имитация системного блюра / кастомные фоны в навигации.** «Prefer to remove custom effects and let the system determine the background appearance». `NSVisualEffectView` внутри сайдбара — прямо запрещён.
4. **Кастомный фон у шитов и поповеров.** «Audit the backgrounds of sheets and popovers… remove those custom background views.»
5. **Тонирование всего подряд.** «When every element is tinted, nothing stands out.» Цвет — только для смысла.
6. **Хардкод системных цветов и высот контролов.** «Avoid hard-coding system color values»; «DO NOT hard-code control heights — use Auto Layout». Контролы в macOS 26 подросли — фиксированные высоты ломают вёрстку.
7. **Кастомная отрисовка оконного хрома.** «Avoid creating custom window UI… Doing so without perfectly matching the system's look can make your app feel broken.»
8. **Ручной overflow-меню в тулбаре** — система добавляет его сама.

**Датировано в 2026 (не копировать со скриншотов Tahoe):**
9. Инсетный «плавающий» стеклянный сайдбар с собственным радиусом внутри радиуса окна — «двойной бортик», откачен в Golden Gate; срок жизни паттерна ≈ 9 месяцев.
10. Очень крупные радиусы (16–20) у окон и карточек на Mac.
11. Монохромные иконки в сайдбаре — цвет вернулся.
12. «Призрачные» тулбары: кнопки, висящие ни на чём, без подложки и разделителя.
13. Иконка на каждом пункте меню (Tahoe переусердствовал; Golden Gate сократил).
14. Глассморфизм как основа, а не акцент; блюр как самоцель; блюр > 60 px; больше 4 композитных слоёв на экран.
15. Неоморфизм — «красив в Dribbble, ловушка доступности в продакшене».
16. Атмосферные градиенты, градиентные бордюры, декоративные тени.
17. Веб-признаки в нативном окне: `cursor: pointer`, hover-lift, 16 px основной текст, настройки в модалке.
18. КАПС в заголовках секций (система больше не апперкейсит — теперь это буквально ваш капс).
19. Полностью прозрачные/«All Clear» иконки приложения — рецензенты «не могли понять, какая иконка какая».
20. Конфетти и «празднования» как механизм восторга.

## 5. ДОСТУПНОСТЬ

Ключевой факт: системные материалы и Liquid Glass реагируют на эти настройки **автоматически**. Наш кастомный HUD — **нет**. Ответственность целиком на нас, и это цена, которую мы платим за §2.1.

**Reduce Transparency** (`NSWorkspace.shared.accessibilityDisplayShouldReduceTransparency`, SwiftUI `\.accessibilityReduceTransparency`):
- HUD и карточки диктовки → полностью непрозрачная заливка (`windowBackgroundColor`, `NSVisualEffectView.state = .inactive` или замена на solid), скрим убрать, hairline сделать видимым бордюром.
- Метод, который стоит принять как правило: **сначала спроектировать solid-версию, потом наложить материал.** Тогда fallback уже существует, а не изобретается.

**Increase Contrast** (`accessibilityDisplayShouldIncreaseContrast`, SwiftUI `\.colorSchemeContrast`):
- Hairline → полноценный бордюр контрастного цвета; `.secondary` текст поднять до `.primary`; убрать полупрозрачные заливки чипов.
- Для каждого кастомного цвета обязаны существовать **четыре** варианта: light, dark, light-increased-contrast, dark-increased-contrast. «Even if your app ships in a single appearance mode, provide both light and dark colors to support Liquid Glass adaptivity.»

**Reduce Motion** (`accessibilityDisplayShouldReduceMotion`, SwiftUI `\.accessibilityReduceMotion`):
- Пружины → мгновенная смена состояния или кросс-фейд 0.1 s.
- Отключить `.drawOn`/`.variableColor`/`.breathe` (или `.symbolEffectsRemoved()`), убрать анимацию перестроения стопки карточек.
- Анимация появления HUD → простое затухание.

**Контраст:** минимумы HIG — 4.5:1 для текста до 17 pt, 3:1 при 18 pt, 3:1 для жирного любого размера. Проверять в **обеих** темах и **после** наложения блюра, а не до. Целевой ориентир для HUD: измерять поверх и светлых, и тёмных обоев.

**Прочее:** каждой иконочной кнопке в тулбаре — accessibility label; каждый пункт тулбара продублировать командой в строке меню (требование HIG для macOS); `window.autorecalculatesKeyViewLoop = true` для корректного Tab-порядка (macOS 26+, гейтить); настройка размера интерфейса из §3.4 закрывает потребность в увеличении для menu-bar-утилиты.

**Ловушка версии, которую компилятор не поймает:** расширение `.glass(_:)` помечено macOS 26.0, но `GlassButtonStyle.init(_ glass:)`, который оно вызывает, помечен **26.1**. Код скомпилируется при target 26.0 и упадёт в рантайме на 26.0. Считать параметризованную форму 26.1+.

**Доступно на macOS 14 без гейтинга** (можно внедрять сразу, и это ~70 % визуального выигрыша):
`.formStyle(.grouped)` + `Form`/`Section`; Title Case в заголовках секций; `.background.secondary`; `.buttonBorderShape(.capsule)`; `ControlSize.extraLarge` (SwiftUI); `.controlSize(.large)`; `.toolbar(removing: .sidebarToggle)`; `.navigationSplitViewColumnWidth(min:ideal:max:)`; `.containerBackground(_:for: .window)` (15.0); `.toolbarBackgroundVisibility` (15.0); `.symbolEffect(.pulse/.bounce/.variableColor/.replace)` (14.0), `.wiggle/.rotate/.breathe` (15.0); `NSVisualEffectView.isEmphasized` (10.12); `window.hasShadow`, `animationBehavior`, `titlebarAppearsTransparent`, `toolbarStyle`; удаление кастомных фонов и теней; вся шкала отступов, радиусов, типографики и движения из §1.

**Стратегия гейтинга.** `@available` на типе `View` вирусен — он заражает все места конструирования. Правильный приём: один `@ViewBuilder`-хелпер на эффект, с рантайм-веткой внутри, чтобы `#available` встречался в коде 4–5 раз, а не 50:

```swift
extension View {
    @ViewBuilder
    func glassCard(radius: CGFloat = 10) -> some View {
        if #available(macOS 26.0, *) {
            self.glassEffect(.regular,
                in: .rect(corners: .concentric(minimum: .fixed(radius)), isUniform: true))
        } else {
            self.background(.regularMaterial, in: .rect(cornerRadius: radius))
        }
    }
}
```

**Стратегический риск и рекомендация по срокам.** `UIDesignRequiresCompatibility` (Info.plist-опт-аут из нового оформления) **игнорируется при сборке против SDK 27** — то есть при переходе на Xcode 27 отказаться уже нельзя. Отсюда порядок работ:

- **Сейчас, без гейтинга:** удалить кастомные фоны и тени внутри окон, перевести Настройки на `Form`/`Section`, привести заголовки к Title Case, убрать захардкоженные высоты контролов, вернуть цвет иконкам сайдбара, применить шкалы отступов/радиусов/типографики, починить HUD (`hasShadow`, `isEmphasized`, `animationBehavior`), переделать Онбординг под правила прайминга и живой чек-лист Accessibility, сделать пустое состояние Словаря.
- **Затем, за `#available(macOS 26)`:** концентричные формы, scroll edge effects, `safeAreaBar`, `.drawOn`, `\.backgroundProminence`.
- **HUD не мигрировать** ни на каком горизонте без подъёма floor до 26 и повторной проверки поведения в Golden Gate — Apple там осознанно усилила различие активного и неактивного окна.
- Отдельная задача вне этого брифа, но с наибольшим весовым коэффициентом «выглядит устаревшим»: **иконка приложения**. На macOS 26+ иконки — слоёные, собираются в Icon Composer, слои подаются квадратными и немаскированными; плоский PNG в старой свободной маковской форме сейчас самый заметный признак старого приложения.
